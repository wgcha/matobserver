# 역공학 SW 개발 계획서 (3점굽힘·압축)

2026-10-24 · 차완기 · 원본: Claude Docs 계획서(다이어그램 포함)

## 개요·목표

시험 하중-변위(F-δ) 곡선을 입력받아, LS-DYNA 해석 곡선이 일치하도록 재료카드 계수를 식별하는 백엔드 SW를 만든다. 대상 시험은 3점굽힘과 압축이다. 식별은 탄성계수와 MAT_024 탄소성(테이블 또는 경화식 계수)이 기본이고, 다른 재료카드는 옵션으로 붙인다. MatNexus의 F-δ → σ-ε 변환 기능을 보완하는 역할로, 응력장이 불균일해 직접 환산이 안 되는 시험을 역공학으로 처리한다. 프런트는 두지 않고 API로 MatNexus에 연결한다.

- 산출물(솔버 중립, 1차): E, ν(입력값 기록), 진응력–진소성변형률 테이블. 계수 모드에서도 테이블로 샘플링해 함께 낸다. 메타데이터로 유효 범위(시편 내 도달 최대 소성변형률), 식별에 쓴 시험 종류, 가정(J2 등방경화, 속도 무관), 잔차를 붙인다. LS-DYNA 카드(.k)는 이 테이블에서 파생한 2차 산출물이고, 타 솔버 카드는 MatNexus 렌더러가 만든다. 곡선 비교와 수렴 이력도 함께 낸다.
- 성공 기준(안): F-δ 오차가 합의 임계값 이하, 동일 입력 재실행 시 결과 재현
- 파단·손상 식별은 범위 밖이다.

대상 재료는 플라스틱, 금속, 실리콘, 유리, IC PKG(육면체 등가화) 등 엔지니어링 재료 전반이다. 유리·실리콘처럼 취성인 재료는 E만 식별한다.

## 범위

| 구분 | 포함 | 제외 |
| --- | --- | --- |
| 재료 | 플라스틱, 금속, 실리콘, 유리, IC PKG(육면체 등가 등방성) | 이방성·적층 복합재(2차 후보) |
| 3점굽힘 형상 | 육면체, STP 임의형상 | 기타 파라메트릭 형상 |
| 압축 형상 | 원기둥, 육면체, 원뿔대(윗면 지름 < 밑면 지름), STP 임의형상 | 중공·다층 시편 |
| 입력 | 시험 데이터(MatNexus 어휘), STP, 기준 재료카드, 파라미터 범위 | 시험 원시데이터 전처리 자동화(1차) |
| 해석 | 형상별 메시 생성(파라메트릭 + STP 사면체/2D), 덱 생성·실행·F-δ 추출 | 사용자 메시 업로드(2차 후보) |
| 식별 | E(기본), MAT_024 탄소성(기본), 기타 재료카드(옵션 플러그인) | 파단·손상, 온도 의존성, 단열 연화(변형률속도는 n차 고속 TestSpec에서만 식별) |
| 연동 | REST API, 잡 상태·결과 조회 | UI, 인증(MatNexus 담당) |

가정: 파라메트릭 형상은 치수로 육면체 메시를 직접 만들고, STP는 오픈소스 메셔(gmsh 등)로 사면체 또는 2D(축대칭·쉘) 메시를 만들고 LS-DYNA 키워드 writer는 직접 작성한다. 형상이 단순해 이 수준으로 충분하다고 본다. 지그·압자·압축판은 강체 템플릿으로 고정한다.

## 시스템 구성

흐름: MatNexus → REST API → JobStore(SQLite) ← 워커: 최적화기(BO) → 형상·메시·덱 생성 → LS-DYNA 실행 → F-δ 추출·목적함수 J → 최적화기 (종료 조건까지 반복). (다이어그램은 Claude Docs 원본 참조)

최적화기가 제안한 θ마다 형상·메시·덱 생성 → 해석 → F-δ 추출 → J 계산을 반복하고, 잡 상태·이력·결과 메타데이터는 JobStore(SQLite)에, 대용량 파일(덱, binout, 카드)만 작업 폴더에 둔다. 파일은 artifact_id로만 내려받는다. 연결 플랫폼은 MatNexus다.

## 모듈 분리·교체 구조

최적화기, 솔버, 재료카드를 독립 플러그인으로 분리한다. 식별 엔진은 세 인터페이스에만 의존하고, 잡마다 설정으로 구현을 고른다. 하나를 바꿔도 나머지 둘과 엔진은 수정하지 않는다.

| 모듈 | 인터페이스(안) | 1차 구현 | 교체 후보 |
| --- | --- | --- | --- |
| 최적화기 | `ask() → θ 목록`, `tell(θ, J)`, `state()/restore()` | BO | SRSM, least-squares, 외부 라이브러리 |
| 솔버 어댑터 | `prepare(model, card, workdir)`, `run(ncpu, timeout) → 상태`, `extract() → F-δ` | LS-DYNA implicit / explicit | 타 솔버, 대리모델(테스트용) |
| 재료카드 | `param_space()`(이름·범위·제약), `to_neutral(θ)`(E, ν, σ-εp 테이블), `capabilities()` | MAT_024 계수 모드, MAT_024 테이블 모드 | MAT_187, 사용자 정의 경화식 |

- 재료카드는 솔버 중립 표현(E, ν, σ-εp 테이블)을 내고, 키워드 작성은 솔버 어댑터가 맡는다. MAT_187처럼 솔버 전용 필드가 필요한 카드는 `capabilities()`로 지원 솔버를 선언하고, 조합이 맞지 않으면 잡 생성 시 400으로 거절한다.
- 플러그인은 설정 파일(레지스트리)에 등록한다. 엔진 코드에 구현 이름을 하드코딩하지 않는다.
- 모든 구현은 같은 인터페이스 계약 테스트를 통과해야 등록된다. 대리모델 솔버 어댑터가 이 테스트의 기준 구현이다.
- 형상·메시 생성기도 같은 방식으로 분리해 둔다(형상 종류별 구현).

### 재료 슬롯과 멀티스케일 등가화

제품 해석에 쓰기 위해 결과는 등가 물성이다. 재료는 처음부터 슬롯 목록으로 정의한다(슬롯마다 재료카드 플러그인 + 고정/식별 여부).

| 모드 | 모델 | 최적화 변수 | 용도 |
| --- | --- | --- | --- |
| A. 단일 등가 | 육면체(또는 STP) 전체에 물성 1개 | 슬롯 1개 | 제품 해석에서 부품을 블록 하나로 넣을 때 |
| B. 요소별 다중 물성 | STP 다중 바디 또는 층상 육면체, 파트·요소 세트별 슬롯 | 선택한 슬롯들의 변수(나머지 고정 카드) | 내부 구조를 남긴 등가 모델 |

- θ는 슬롯별로 분할되고, 결과도 슬롯별 테이블로 낸다.
- 식별성 진단은 엔진 기능이다: 식별 변수 수 대비 데이터 수 점검, 민감도·상관 계산, 부족 시 경고와 고정 권고, 서로 다른 스팬·방향 시험의 동시 피팅.
- 등가 물성은 하중 모드·형상에 의존하므로 결과 메타데이터에 등가화 대상 구성과 하중 모드를 기록한다.
- 1차 구현: 모드 A 전체 + 모드 B는 슬롯별 E(탄성 다중 물성). 모드 B 탄소성은 2차 이후.

## 구현 단계와 데이터 교류 원칙

구현은 1차 3점굽힘, 2차 압축 순으로 나눈다. 데이터 교류 계약(입력 어휘, 응답 정의, 기준축, 결과 스키마)은 1차에서 n차까지 수용하도록 확정하고, 이후 단계는 계약에 추가만 한다(하위 호환, `schema_version` 관리).

| 단계 | 시험 | 형상 | 해석 모드 | 이 단계에서 여는 것 |
| --- | --- | --- | --- | --- |
| 1차 | 3점굽힘 | 육면체, STP | implicit 준정적 | 엔진, 플러그인 5종 인터페이스, 레시피(파라미터형·고정) 등록·검증, 컴플라이언스 보정, 재료 슬롯(모드 A, 모드 B 탄성), 식별성 진단, 다중 시험 동시 피팅, 정렬 규칙, 결과 메타데이터, MatNexus 연동 |
| 2차 | 압축 | 원기둥, 육면체, 원뿔대, STP | implicit 준정적 | μ 식별, 축대칭 모델, 스칼라 응답(배럴링), 모드 B 탄소성 |
| n차 | 전단, 고속, 임의 시험 | TestSpec별 | explicit 동적 포함 | 시간 기준축, 속도 의존 식별, 범용 TestSpec |

## 시험 정의(TestSpec)와 데이터 정렬 규칙

시험 종류는 TestSpec 플러그인으로 분리하고, 시험과 해석 곡선은 TestSpec이 선언한 기준축 위에서 하나의 규칙으로 비교한다. 새 시험은 TestSpec을 추가해 대응하고 엔진은 고치지 않는다.

| TestSpec 구성 | 내용 |
| --- | --- |
| 데이터 매핑 | MatNexus `test_type_key`·채널·치수 키 → 내부 모델 |
| 지그·경계조건 | 강체 지그, 구속, 하중 경로(변위 제어 / 초기속도·질량) |
| 허용 형상 | 사용할 수 있는 형상 플러그인 목록 |
| 응답 정의 | `[{시험 채널, 해석 추출기, 기준축, 가중치, 구간}]` — 곡선·스칼라 모두 |
| 해석 모드 | 준정적(implicit 우선) / 동적(explicit) |
| 검증 규칙 | 필수 채널·치수, 형상 조합 |

범용 TestSpec을 하나 둔다. 사용자가 지그 덱(.k include)과 응답 정의를 주면 코드 추가 없이 실행하고, 자주 쓰는 시험은 전용 TestSpec으로 승격한다. 매핑이 없는 시험 종류는 잡 생성 시 거절한다.

### 레시피(지그·경계조건) 구조

엔진은 항상 "레시피 + 파라미터 → 덱"만 처리한다. 파라미터형 템플릿도 레시피의 한 종류다. 지그가 바뀌면 레시피를 등록하고, 엔진 코드는 고치지 않는다.

| 구분 | 파라미터형 레시피 | 고정 레시피 |
| --- | --- | --- |
| 대상 | 3점굽힘 표준 지그(D790, ISO 178 등), 압축판 | 사내 전용 지그, 복잡한 치구, 임의 시험 |
| 생성 | matobserver가 치수로 지그·시편 메시 생성 | 관리자가 완성 덱(.k) 등록 |
| 가변값 | 스팬, 압자 R, 지지 R, 시편 L·W·T, 오버행, 속도, 마찰 | `*PARAMETER`로 노출한 값만 |
| 재료 | 재료 슬롯 `*INCLUDE` | 같음(슬롯별 part ID 지정) |

- 매니페스트: `recipe_id@version`(불변·해시), 시험 종류, 단위계, 재료 슬롯 목록(part/요소 세트), 시편 슬롯(파라메트릭 치수 또는 STP 배치 규약: 원점, 하중 축, 초기 간격 0), 노출 파라미터(이름·범위·MatNexus 치수 키 매핑), 응답 정의(RCFORC/NODOUT ID ↔ 시험 채널), 권장 시편 요소 크기, 장비+지그 컴플라이언스 C.
- 등록: 관리자만 가능하다. 1차는 폴더(덱 + 매니페스트 yaml) + CLI `matobserver recipe add <폴더>`, 내부적으로 관리자 토큰 API를 함께 둔다. MatNexus 관리자 화면 연동은 추후 협의.
- 등록 검증(Verifier 대상): 기준 카드 dry-run(정상 종료, 응답 추출, 단위 일관성, 시편–지그 관통 검사, 메시 수렴), 질량 스케일링·감쇠·하드코딩 재료 경고.
- 일반 잡은 `recipe_id@version`과 치수만 넘긴다. 잡은 레시피 버전을 참조하므로 결과가 재현된다.

### 변위 채널과 컴플라이언스 보정

- 3점굽힘 기본 변위는 크로스헤드다. δ_시편 = δ_크로스헤드 − C·F로 보정한다. C는 E와 구분되지 않으므로 식별 변수로 두지 않고, 장비+지그 조합별 교정값(강체 블록·강재 시편 측정)으로 레시피에 등록한다.
- C가 없으면 잡은 실행하되 결과에 "E 신뢰도 낮음" 경고를 붙인다. 처짐계 채널이 있으면(옵션) 그 채널을 쓰고 보정은 생략한다.

### 정렬·재샘플링 규칙(표준, 1차부터 적용)

1. 정규화: SI 변환, 중복 x 제거, 기준축이 단조인 하중 구간만 사용(제하 구간 제외).
2. 기준축: 준정적은 변위, 고속은 시간. 응답마다 TestSpec이 선언한다.
3. 원점 정렬: 하중이 피크의 설정 비율을 넘는 점을 접촉 시작으로 보고 시험·해석에 같은 규칙을 적용한다. 준정적은 토우 보정 후 원점을 잡고, 고속은 시간 이동량을 범위가 제한된 보조 변수로 둘 수 있다.
4. 비교 구간: 시험 범위 ∩ 해석 범위 ∩ 사용자 절단점. 끝은 파손 판정(피크 대비 하중 급락)으로 자동 절단한다.
5. 공통 격자: 구간을 N점 균일 격자로 재샘플링한다(N은 설정값). 탄성 구간에 최소 점 수를 보장해 구간 가중이 원본 샘플 밀도에 좌우되지 않게 한다.
6. 보간·필터: 양쪽 모두 선형 보간. 필터는 시험과 해석에 같은 것을 적용한다(고속은 CFC 계열). 한쪽만 거르면 위상차가 오차로 남는다.
7. 해석 출력 간격: 격자 간격에서 역산한다(출력 간격 ≤ 격자 간격 / k, k는 설정값). 덱 생성 시 binout 출력 간격으로 넣는다.
8. 범위 부족: 해석이 비교 구간 끝 전에 멈추면 미도달 비율만큼 페널티를 더한다.

### 고속 시험(n차, 계약만 1차에 반영)

- 데이터: 시간–하중이 기본이고 시간–변위·충격체 속도는 있으면 쓴다. 변위가 없으면 시험의 초기속도·충격체 질량 또는 측정 속도 이력을 해석 경계조건으로 쓴다.
- 솔버: explicit 동적, 질량 스케일링 금지(쓰면 운동에너지 비율 검증을 조건으로). 해석 시간이 짧아 4코어에서도 감당 가능하다.
- 해석 모드 선택: 공칭 변형률속도가 임계값(설정값)을 넘으면 explicit 동적, 아래면 implicit 준정적.
- 재료: 준정적 테이블을 먼저 확정·고정한 뒤 고속 시험으로 속도 계수(Cowper–Symonds C, p) 또는 속도별 테이블을 식별한다. 산출물은 σ(εp, ε̇p) 테이블로 확장되며 MatNexus dyna 렌더러의 속도별 표와 맞는다.
- 신호: 로드셀 링잉·지그 관성이 크면 지그와 로드셀을 모델에 포함한다. 시간 이력 유사도는 L2 외에 ISO 18571(CORA 계열) 지표를 옵션으로 둔다.

## 방법론

식별은 E 고정 → 탄소성 식별의 2단계로 하고, 탄소성 단계는 베이지안 최적화(BO)를 기본안으로 한다. 해석 1회 비용이 커서 평가 횟수를 줄이는 것이 핵심이다.

1. 탄성: 초기 기울기로 E를 정한다. 파라메트릭 형상은 해석식(굽힘: 보 이론, 압축: 단면적·높이)으로 초기값을 잡고 FE 1D 탐색으로 보정한다. STP 형상은 해석식 없이 FE 1D 탐색만 한다.
2. 탄소성: 출력 형식을 두 모드로 둔다.
    - 계수 모드: Swift/Voce 등 경화식 계수(σy, K, n 등)를 식별하고 MAT_024 커브로 변환한다.
    - 테이블 모드: 유효소성변형률 노드의 응력값을 설계변수로 직접 식별한다(단조 증가 제약, 노드 수는 설정값).

압축 시험은 압축판 마찰이 배럴링과 하중에 영향을 준다. 윤활 없는 시험이 기본이므로 마찰계수 μ는 식별 변수로 두고, 값을 알 때만 고정한다. 시험 후 배럴링 최대 지름이 있으면 목적함수에 추가해 μ와 경화 계수의 상관을 줄인다. 원뿔대는 작은 단면에서 소성이 먼저 시작되므로 소성 구간 곡선이 형상에 더 민감하다.

목적함수(안): δ 기준으로 재샘플링한 두 곡선의 구간별 정규화 오차 가중합. Ω1은 탄성 구간, Ω2는 소성 구간이다.

```latex
J(\theta) = \sum_{k=1}^{2} w_k \frac{\lVert F_{sim}(\delta;\theta) - F_{exp}(\delta) \rVert_{2,\Omega_k}}{\lVert F_{exp} \rVert_{2,\Omega_k}}
```

- 재료모델: E는 MAT_001(탄성 전용, 유리·실리콘·IC PKG 등가)로, 탄소성은 MAT_024로 기본 식별한다. MAT_187(SAMP) 등 다른 카드는 옵션 플러그인으로 둔다.
- 알고리즘 대안: BO(기본) / SRSM 응답면 / 차분 기반 least-squares(국소 보정용).
- 종료 조건: 해석 예산 N회 도달, 또는 J 개선이 연속 k회 임계값 미만.
- 솔버 노이즈(접촉, 질량 스케일링) 영향을 줄이기 위해 출력 필터와 시간 스케일링 설정을 템플릿에 고정한다.

피팅은 LS-DYNA와 재료카드로 하지만, 결과는 솔버 중립 테이블로 확정한다. Verifier는 이 테이블로 1요소 단축 덱을 다시 돌려 입력 테이블이 재현되는지 왕복 검사한다. 유효 범위 밖은 외삽으로 표시하고, 외삽 방식(마지막 기울기 유지 또는 경화식 연장)은 메타데이터에 남긴다.

## 해석 실행 전략 (로컬 4코어)

API 프로세스와 워커 프로세스를 분리한다. API는 잡을 JobStore(SQLite)에 등록·조회만 하고, 워커가 큐에서 잡을 꺼내 실행한다. 로컬 PC는 최대 4코어이므로 워커는 1개, 잡은 한 번에 1건, 해석은 순차로 실행한다. SMP와 MPP 모두 기존 사내 배치 실행 방식을 솔버 어댑터가 감싸서 호출한다(배치 정보는 별도 수령). 병렬 평가 대신 해석 1회 시간을 줄이는 것이 우선이다.

| 수단 | 적용 형상 | 효과 |
| --- | --- | --- |
| 축대칭 2D 모델 | 원기둥·원뿔대 압축 | 3D 대비 요소 수 대폭 감소 |
| 1/4 대칭 모델 | 육면체 굽힘·압축 | 요소 수 1/4 |
| 내재적(implicit) 정적 해석 우선 | 파라메트릭 형상 | 질량 스케일링 불필요, 스텝 수 감소. 수렴 실패 시 외재적으로 자동 전환 |
| 요소 수 상한 | STP | 상한(설정값) 초과 시 메시 조대화 |
| 1회 해석 시간 상한 | 전체 | 초과 시 강제 종료 후 페널티 J |

LS-DYNA 1회 실행 루틴:

1. 형상·메시·덱 생성 → 실행 번호별 작업 폴더
2. 사내 배치 스크립트로 SMP/MPP 실행, 시간 상한 감시
3. 종료 판정: `d3hsp`/`messag`에서 Normal/Error termination 확인. 라이선스 오류는 대기 후 재시도
4. `binout`(RCFORC/NODOUT)에서 F-δ 추출 → J 계산
5. 대용량 결과(`d3plot`)는 최적점만 남기고 정리 — 작업 폴더 내부에서만 삭제

- 평가 수 절감: 원기둥 압축은 직접 환산값, 굽힘은 보 이론 값을 BO 초기점으로 쓴다. 잡당 평가 수 상한은 설정값으로 둔다.
- 압축 잡은 시작 시 μ 민감도 체크(μ = 0, 0.3 각 1회)를 자동 수행하고, 소성 구간 하중 차이가 작으면 μ를 고정한다.

## 시험 데이터 입력: MatNexus 어휘 채택

중립 포맷을 새로 정의하지 않고 MatNexus 어휘를 그대로 쓴다. MatNexus가 시험종류·채널·시편 치수를 SI로 표준화해 저장하므로 입력 스키마로 충분하다. 해석 단위계(mm·N·MPa·s) 변환은 이 SW가 한다.

| 항목 | MatNexus 원천 | 사용 |
| --- | --- | --- |
| 시험종류 | `flexural`(FLX), `compression`(CMP) | `test_type` 매핑 |
| 채널 | force(N), displacement(m), deflection(m), strain(1), time(s) | F-δ 구성. 크로스헤드/처짐계 선택 규칙 필요 |
| 시편 치수 | 굽힘: width, thickness, span, load_span / 압축: 높이, 면적 | 파라메트릭 형상 생성. load_span 유무로 3점·4점 판별 |
| 시험 조건 | temperature(K), test_speed(m/s) | 기록용 |
| 곡선 | `GET /api/test-runs/{id}` + `/curve`(최대 5000점 다운샘플) 또는 `/source` 원본 | 시편별 F-δ |
| 반복 | Specimen → TestRun n개 | 다중 곡선 동시 피팅 |
| 인증 | 개인 토큰(PAT) | 서비스 계정 토큰 |

- 입력 경로: 잡 요청에 `test_run_ids`를 넘기면 SW가 MatNexus에서 직접 가져온다. MatNexus 밖 데이터는 같은 어휘의 JSON으로 받는다(오프라인·테스트용).
- MatNexus에 없어 이 SW가 정의하는 것: STP 형상 참조, 원뿔대 치수(윗면·밑면 지름, 높이), 원기둥 지름, 압축판 마찰·윤활, 배럴링 지름.
- 결과 반입: MatNexus에는 외부 결과를 받는 API가 아직 없다. ADR 0026(제안 상태)의 InverseRun·EstimatedProperty 설계가 이 SW 결과 구조(입력 run, 자유 파라미터, 잔차 곡선, 추정 물성+불확도)와 맞으므로, 이를 구현해 결과를 draft 카드로 등록하는 방향으로 협의한다.
- 카드 키워드: MatNexus의 기존 dyna 렌더러(*MAT_001, *MAT_024 표)를 재사용할 수 있다. 이 SW는 결과를 MatNexus 카드 블록 어휘(elastic, table: plastic_strain/true_stress)로 반환하는 것을 기본으로 하고, 재료카드 플러그인의 `to_neutral()`도 이 어휘에 맞춘다.
- 비동기: MatNexus에 콜백·웹훅 계약이 없으므로 MatNexus가 잡 상태를 폴링한다.
- 검증 자산: MatNexus의 1요소 검증 덱(예: dp600-1elem-lsdyna.k)을 Verifier의 키워드 왕복 테스트에 쓴다.

## API 계약 초안

비동기 잡 모델로 간다. 식별 1건이 수 시간 걸릴 수 있어 제출과 조회를 분리한다. 확정본은 `docs/contracts/api.md`에 둔다.

| 메서드 | 경로 | 용도 | 주요 응답 |
| --- | --- | --- | --- |
| POST | `/v1/files` | STP 등 입력 파일 업로드 | `file_id` |
| POST | `/v1/calibrations` | 잡 생성(시험 데이터, 형상, 기준 카드, 파라미터 범위) | `job_id` |
| GET | `/v1/calibrations` | 잡 목록(상태·기간·재료 필터, 페이지) | 잡 요약 목록 |
| GET | `/v1/calibrations/{id}` | 상태·진행률 | `status`, `iter`, `best_J` |
| GET | `/v1/calibrations/{id}/result` | 최종 결과 | E, 진응력–진소성변형률 테이블, 메타데이터, `artifact_id` 목록 |
| GET | `/v1/calibrations/{id}/history` | 반복 이력 | θ, J 목록 |
| POST | `/v1/calibrations/{id}/cancel` | 중단 | `status` |
| GET | `/v1/artifacts/{id}` | 파일 다운로드(카드 .k, 곡선, 덱) | 파일 스트림 |

- 요청 핵심 필드: `test_type`(TestSpec 레지스트리 키: bending, compression, …), `geometry`(kind: box | cylinder | frustum | stp, 치수 또는 STP 파일 ID), `test_run_ids`(MatNexus), `plasticity_mode`(coeff | table), `optimizer`·`solver`·`material_model`(레지스트리 이름), `friction`(값 또는 식별)
- 잡 상태: `queued → running → succeeded / failed / cancelled`
- 입력 검증 실패는 잡 생성 전 400으로 반환한다(곡선 단조성, 파라미터 범위, 형상·시험 조합, STP 읽기 가능 여부).
- 결과 파일은 잡별 작업 폴더에만 쓰고, MatNexus에는 경로를 노출하지 않고 다운로드 URL(`artifact_id` → `GET /v1/artifacts/{id}`)로만 넘긴다.

## 일정·마일스톤

1차(3점굽힘) 약 9주(안): 1. 계약 1주 → G1 계약 승인 → 2. 핵심 구현 4주(메시·덱·실행기·API, 최적화(대리모델)) → G2 가상 역식별 통과 → 3. 통합·검증 2주(LS-DYNA 루프 연결, Verifier 검증) → G3 Verifier Pass → 4. 실시험 적용 2주(굽힘 곡선 식별, 플랫폼 연동) → G4 성공 기준. (다이어그램은 Claude Docs 원본 참조)

1차(3점굽힘) 기준이며, 레시피·컴플라이언스·슬롯 구조 추가로 1~2주 늘어날 수 있다(G1 이후 재산정). 2차(압축)는 1차 G4 이후 별도 일정으로 잡는다. 기간은 초안이며(STP 메시 추가로 핵심 구현 1주 증가), 해석 자원과 대상 재료군이 정해지면 확정한다. G2(해석해 기반 가상 곡선에서 계수 복원)를 통과해야 솔버 통합으로 넘어간다.

- [ ] 사내 LS-DYNA 배치 실행 정보(SMP/MPP 호출 방식, 라이선스 대기 처리)
- [ ] 탄소성 출력 기본 모드(계수 / 테이블)와 경화식 종류
- [ ] 성공 기준 오차 임계값과 잡당 해석 예산(N회, 시간)
- [ ] MatNexus 연동 방식(인증, 결과 전달 형식)과 실행 환경(LS-DYNA 버전, 라이선스 형태, OS; 로컬 최대 4코어는 확정)
- [ ] 시험 데이터 포맷, 압축 마찰계수 확보 여부
- [ ] MatNexus 협의: 결과 반입 경로(ADR 0026 inverse 구현 또는 parameter-set 직접 입력), 원본 곡선 해상도(/source 사용), 변위 채널 선택, 압축 시편 치수 키 추가
